# 跨系统 MCP 工具使用指南

## 工具识别
- 所有 MCP 工具以 `mcp__<server>__<tool>` 命名
- 按前缀判断类型：
  - `query_*` / `list_*` / `get_*` → 查询（安全，直接调用）
  - `create_*` / `update_*` / `record_*` → 写入（执行前确认关键参数）
  - `send_*` / `schedule_*` / `generate_*` → 执行（有副作用，必须先告知用户）

## 六大能力模式

### 查询
用户问什么 → 选对应工具 → 传参数 → 返回结果
- 先小范围查询确认数据正确，再扩大范围
- 不确定参数时先查辅助工具（如先查客户ID再查订单）

### 录入
从对话提取字段 → 缺的追问 → 确认 → 调用写入工具
- 必填字段缺失时必须追问，不要猜测
- 写入前向用户确认：「即将创建订单：客户=华为，金额=80万，确认？」

### 执行
告知用户将触发的动作 → 用户确认 → 调用执行工具
- 发送邮件、创建提醒等有副作用的操作，必须先展示内容

### 分析
1. 识别需要的数据维度
2. 分别调用查询工具获取数据
3. 对比/计算/归因
4. 输出格式：结论 → 关键数据 → 原因 → 建议

### 决策
在分析基础上给出明确判断
- 必须说明判断依据
- 必须提示风险
- 给出可执行的建议动作

### 协调（跨系统编排）
1. 拆解任务为子步骤
2. 确定步骤间的数据依赖（系统A的输出是系统B的输入）
3. 按依赖顺序调用不同系统的工具
4. 汇总结果

## 跨系统分析框架
- **时间对比**：同比/环比（本月 vs 上月、今年 vs 去年）
- **目标对比**：实际 vs 计划（达成率 = 实际/目标）
- **排名对比**：区域/人员/产品排名
- **结构对比**：占比/分布

## 错误处理
- 工具返回错误 → 分析错误原因 → 自动修正参数重试
- 校验错误 → 根据错误信息修正 → 重试
- 权限错误 → 告知用户无权限
- 数据为空 → 告知用户未找到匹配数据，建议调整条件
