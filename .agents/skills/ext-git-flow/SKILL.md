# Git 工作流

DeepSeek Harness 代理的 git 安全规范。无 Cordis 插件。
**主机/群组 URL 和凭据留在工作区 `AGENTS.md` 或机器凭据管理器中——绝不写在此技能里。**

## 何时加载

- 开始实现但目标仓库未验证
- 涉及 `dev` / `prd` 的克隆、提交、推送、MR、分支切换或合并
- 会话早期 git 探测失败，需要恢复工作

## 运行时强制（git-guard）

`git-guard` 插件通过 `tools/pre-execute` 在运行时拦截：`git init`、`--force` 推送、推送到保护分支（`prd`），以及任何推送前的用户确认。

**本技能覆盖 git-guard 不强制的部分**——URL 解析、访问探测、分支选择、冲突恢复。两者互补，不重复。

## 仓库门禁

此门禁通过前，不要计划或编辑产品代码。

### 1. 解析 URL

按优先级：

1. 工作区已是带 `origin` 的 git 检出 → 显示 `git remote -v` 并与用户确认是目标项目
2. 工作区 `AGENTS.md` 只记录了默认**群组** → 询问**项目名或完整 URL**（绝不在群群下编造路径）
3. 否则 → 一次性询问 HTTPS 或 SSH git URL（可用时用 `ask_user_question`）

绝不在聊天中询问密码或令牌。

### 2. 探测（非破坏性）

失败时停止；报告分类后的原因（网络、认证、未找到、禁止、超时）：

| 检查项 | 方法 |
|---|---|
| 可达/读 | `git ls-remote <url>` 或 `git ls-remote origin` |
| 本地状态 | `git status -sb`、当前分支、干净/脏 |
| 分支策略 | 在 `dev` 上工作（或基于 `dev` 的短生命周期分支）。拒绝在 `prd` 上提交功能 |
| 写入（承诺交付前优先验证） | 当检出存在且预期有远程更新时，`git push --dry-run origin HEAD:dev` |

不要打印凭据或 `.env` 内容。

### 3. 落地检出

- 只有 URL → **`git clone`** 到工作区（或用户命名的子目录）；优先复用已有干净检出而非重新克隆
- **绝不 `git init`。** 没有远程 URL → 停止并询问用户
- 如果宿主会话 cwd 仍在父文件夹，告知用户在需要时将克隆作为工作区打开

## 分支策略

| 分支 | 角色 |
|---|---|
| `dev` | 开发和测试——默认集成分支 |
| `prd` | 生产——无功能提交；仅在用户**明确**确认后提升/合并 |

- 绝不 force-push `dev` 或 `prd`
- 当远程保护分支时优先用合并请求；策略禁止时不要用直接推送绕过
- 短生命周期分支：基于 `dev`，命名简短，开 MR 到 `dev` 除非用户另有指定

## 提交和推送

1. 提交前显示 `git status` 和简洁的 diff 摘要
2. 提交信息：重为什么而非做了什么；遵循仓库已有风格
3. 绝不提交：`.env`、密钥、`.wiki/`、构建产物或凭据文件

## 冲突和恢复

- 遇到冲突或未预期的脏树：**停止**，总结冲突路径，提出 rebase vs merge 选项；未经明确要求不要重写共享历史
- 不要 `reset --hard` 或删除分支，除非用户明确要求
- 如果 `ls-remote` / 推送失败：引导 VPN、凭据管理器、SSH agent 或访问申请——然后重新运行门禁

## 多仓库

如果任务跨多个远程：在编辑每棵树之前，对**每个**仓库运行门禁（URL + 探测 + 分支）。不要假设一个 `origin` 覆盖所有。

## 超出范围

- 公司主机名默认值 → 工作区 `AGENTS.md`
- 每项目测试/发布检查清单 → 该仓库的 README / `AGENTS.md`
- 实现产品功能 → 此门禁通过后用 `dev-loop`
- Wiki 摄入 → `llm-wiki`
