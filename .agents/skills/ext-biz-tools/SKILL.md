# 跨系统业务工具使用指南

## CRITICAL: 强制规则

**MUST**：用最少的工具调用完成任务
- ✅ 第一次查询获取全部需要的字段和数据，后续用 bash/python 本地处理
- ✅ 报错后根据错误信息修正参数，不要忽略错误继续其他查询
- ❌ 禁止对同一实体调用超过 3 次查询工具
- ❌ 禁止调用不存在的工具（幻觉工具名）
- ❌ 禁止用不同参数重复查询相似数据

## 工具识别
- 外部工具通常以 `mcp__<server>__<tool>` 或 `db__<tool>` 等命名
- 按前缀判断类型：
  - `query_*` / `list_*` / `get_*` / `select_*` → 查询（安全，直接调用）
  - `create_*` / `update_*` / `record_*` / `insert_*` → 写入（执行前确认关键参数）
  - `send_*` / `schedule_*` / `generate_*` / `execute_*` → 执行（有副作用，必须先告知用户）

## 六大能力模式

### 查询
用户问什么 → 选对应工具 → 传参数 → 返回结果
- 先小范围查询确认数据正确，再扩大范围
- 不确定参数时先查辅助工具（如先查 ID 再查详情）
- **多视图场景**：根据用户意图选择视图（如 `*_owner` / `*_all` / `*_approval`），不确定时主动询问

### 录入
从对话提取字段 → 缺的追问 → 确认 → 调用写入工具
- 必填字段缺失时必须追问，不要猜测
- 写入前向用户确认：「即将创建订单：客户=华为，金额=80万，确认？」

### 执行
告知用户将触发的动作 → 用户确认 → 调用执行工具
- 发送邮件、创建提醒等有副作用的操作，必须先展示内容

### 分析
1. 识别需要的数据维度
2. 分别调用查询工具获取数据
3. 对比/计算/归因
4. 输出格式：结论 → 关键数据 → 原因 → 建议

### 决策
在分析基础上给出明确判断
- 必须说明判断依据
- 必须提示风险
- 给出可执行的建议动作

### 协调（跨系统编排）
1. 拆解任务为子步骤
2. 确定步骤间的数据依赖（系统A的输出是系统B的输入）
3. 按依赖顺序调用不同系统的工具
4. 汇总结果

## 跨系统分析框架
- **时间对比**：同比/环比（本月 vs 上月、今年 vs 去年）
- **目标对比**：实际 vs 计划（达成率 = 实际/目标）
- **排名对比**：区域/人员/产品排名
- **结构对比**：占比/分布

## 错误处理
- 工具返回错误 → 分析错误原因 → 自动修正参数重试
- 校验错误 → 根据错误信息修正 → 重试
- 权限错误 → 告知用户无权限
- 数据为空 → 告知用户未找到匹配数据，建议调整条件

## 工具调用效率优化

### 原则 1：参数计算只做一次
- ❌ 多次调用 bash 计算时间戳
- ✅ 一次计算所有参数，后续直接引用

### 原则 2：数据一次获取，本地处理
- ❌ 多次调用查询工具（entity-query / db_query 等），每次只改一个参数
- ✅ 一次获取全部原始数据，用 bash/python 本地分组、聚合、排序

### 原则 3：字段一次查全
- ❌ 先查 ID，再查详情，再查关联数据
- ✅ 第一次查询包含所有需要的字段（包括 label、关联对象名称）

### 原则 4：并行调用无依赖工具
- ❌ 串行调用多个独立查询
- ✅ 同一轮并行调用（判断标准：工具 A 的输出不是工具 B 的输入）

### 原则 5：先验证再批量
- ❌ 直接查询 10000 条数据
- ✅ 先查询 5-10 条验证字段名和结构，确认无误后扩大范围

### 效率对比
**低效**：bash×2 → query×6 → bash×1 = **9 次调用**
**高效**：bash×1 → query×1 → bash×1 = **3 次调用**
**关键**：一次获取全部数据，本地处理所有分组/聚合/排序

## 高级查询优化

### 标准流程：分页拉取 → CSV 导出 → 本地分析
1. **分页拉取**：用 entity-search 拉取原始数据（pageSize=50，最多 10 页 = 500 条）
2. **CSV 导出**：用 write 工具把数据写成 CSV 文件
3. **本地分析**：用 bash 运行 python 读取 CSV，做 GROUP BY / SUM / COUNT / 多维交叉分析

### 硬规则
- **同一实体最多查询 5 次**（entity-query + entity-search 总计）
- **超过 5 次必须停止**，用 bash/python 本地处理已有数据
- **优先多维 GROUP BY**：一次查询返回多个维度的交叉分析（如 `GROUP BY status, dimDepartId, saleStageId`）
- **时间序列一次查完**：用 `DATE_TRUNC('week', createdAt)` 一次返回所有周的数据

### 示例
```python
# 拉取 500 条商机后，本地分析
import csv
with open('data.csv') as f:
    data = list(csv.DictReader(f))
# 按部门统计
by_dept = {}
for row in data:
    dept = row['dimDepartId']
    by_dept[dept] = by_dept.get(dept, 0) + 1
```
