# DeepSeek Harness 上的 LLM Wiki

可移植的 [nvk/llm-wiki](https://github.com/nvk/llm-wiki) 行为。无 npm 包，无 Cordis 插件——本技能即集成面。

完整协议：[上游 AGENTS.md](https://github.com/nvk/llm-wiki/blob/master/AGENTS.md)。本文件在其之上增加 DSH 特有的触发条件与约束。

## DSH 触发条件

在**首个**匹配轮次加载：

| 加载 | 不加载 |
|------|-------------|
| 用户提到 wiki/知识/入库/ingest | 用户上传文档**且**说明了明确任务 |
| `.wiki/_index.md` 存在**且**文档上传无任务 | 用户继续已有任务轮次 |
| `.wiki/inbox/` 有尚未归入 `raw/` 的文件 | 无 `.wiki/` 且用户未提及 wiki |
| 用户提问可从项目本地知识回答 | |

## 硬约束（先读）

- 不用 `bash ls/find/cd` 侦察——直接读 `_index.md`
- 用户说明意图前不复制到 `raw/`/`work/`/`.wiki/`
- 不重复提取——如果 `work/<name>.txt` 已存在则复用
- 用户确认 wiki 用途前不创建 `.wiki/`
- 代码轮次：**只读**使用此技能。不摄入、编译、初始化或变更 `.wiki/`

## DSH 约束

### 无任务上传

文档到达不是任务。**回复前不启动任何审计、报告、重写或回答。**

**工作流：**

**第 1 步：识别（≤1 次调用）**
1. 读首页/标题。命名文档和类型。

**第 2 步：推断意图（1 次调用）**
2. 读 `.wiki/_index.md` + `.wiki/log.md` 尾部。如果 `.wiki/` 为空，仅按文档类型排序。

推断原则：文档越正式/有约束力（法规、合同、标准），越偏向审查/合规方向；越偏信息性（论文、报告、数据），越偏向知识库/总结方向。未匹配已有 wiki 时，按此原则自行判断。

既有 wiki 偏向：如果 `.wiki/` 已有主题 wiki 且范围匹配，优先推荐加入该 wiki。

**第 3 步：确认意图（1 次调用）**
3. 先问意图：**"这份文档你想用来 **A. 作为 wiki 知识页入库** 还是 **B. 仅参考查询**？"** 用户确认入库后再问具体操作（归入哪个主题、新建 wiki 等）。

**第 4 步：执行**
4. 仅归档在摄入后停止。否则：先归档源文件（`raw/` + `log.md` 行），再运行任务。

当消息已说明任务，或文件在已有任务中到达时，**跳过询问**。

### 初始化

当触发条件匹配且 `.wiki/_index.md` 缺失时，静默创建骨架：

```
.wiki/
  inbox/          # 投放区
  raw/            # 不可变源
  wiki/
    concepts/
    topics/
    references/
  output/         # 生成产物
  _index.md       # 标题 + 范围 + 到 raw/wiki/inbox 的链接
  schema.md       # 命名规则、wikilink 风格、页面类型约定
  log.md          # 仅追加活动
```

仅当用户想要私有 wiki 时才把 `.wiki/` 加到 `.gitignore`。
